# Changelog

Все значимые изменения в проекте будут документироваться в этом файле.

## [1.4.0] - 2026-09-23

### Исправлено
- Основная причина заполнения диска на сервере: `pkill -9` не давал Chromium убрать временный каталог профиля (`org.chromium.Chromium.scoped_dir.*` в `/tmp/snap-private-tmp/snap.chromium/tmp/`) — за счёт запуска раз в 5 часов копилось ~18 ГБ за полтора месяца
- Новый модуль `browser_cleanup.py`: завершение процессов Chromium/Chrome/chromedriver теперь мягкое (SIGTERM → пауза → SIGKILL только как крайняя мера)
- Автоматическая уборка осиротевших временных профилей Chromium перед каждым запуском и после него
- Проверка свободного места на диске перед запуском браузера (порог 2 ГБ), с явным предупреждением в лог и принудительной уборкой — заполненный диск раньше маскировался под `InvalidSessionIdException`
- Обработка `SIGTERM` (`systemctl stop`) в `scheduler.py`: браузер теперь закрывается штатно через `driver.quit()`, а не остаётся зависшим процессом

### Добавлено
- Автоматическая очистка старых скриншотов ошибок (`logs/*.png`, старше 7 дней) — ранее не покрывались ротацией `loguru` и оставались навсегда
- Автоматическая очистка старых версий ChromeDriver в кэше `~/.wdm` (оставляются последние 2)

## [1.3.0] - 2026-06-19

### Исправлено
- `InvalidSessionIdException`: проверка живости сессии браузера и пересоздание драйвера при падении Chromium
- Повторные попытки в планировщике с перезапуском браузера при `WebDriverException`

### Изменено
- Рекомендуемые требования к серверу: 1 ГБ RAM, 30 ГБ диск
- Команда rsync: исключены `.git`, `.DS_Store`, `logs/` (не заливаются на сервер)

## [1.2.0] - 2026-02-24

### Исправлено
- Устранена проблема с ReadTimeoutError (Chromium падал из-за нехватки памяти)
- Добавлена автоматическая очистка зомби-процессов Chromium/Chrome перед и после каждого запуска
- Добавлены повторные попытки (до 2 раз) при ошибке поднятия резюме
- Добавлено логирование состояния памяти для диагностики

## [1.1.0] - 2026-01-20

### Добавлено
- Поддержка нескольких резюме (поднятие всех за один запуск)
- Настройка через `RESUME_IDS` (список ID через запятую)
- Оптимизация авторизации: одна авторизация на все резюме
- Проверка авторизации перед повторным входом (флаг `_is_logged_in`)

## [1.0.0] - 2025-12-09

### Добавлено
- Автоматическая авторизация на hh.ru через веб-интерфейс
- Поднятие резюме в поиске
- Определение статуса резюме (уже поднято или в кулдауне)
- Обнаружение капчи с предупреждениями
- Поддержка Chromium и Chrome браузеров
- Работа в headless режиме для серверов
- Планировщик для автоматического запуска каждые 5 часов
- Systemd сервис для автозапуска
- Подробное логирование всех действий
- Сохранение скриншотов при ошибках

### Исправлено
- Многошаговая авторизация на hh.ru
- Поиск элементов через множественные селекторы
- Обработка динамических элементов страницы
- Работа с ограниченной памятью на сервере (512 МБ RAM)

### Протестировано
- ✅ Локальная разработка (macOS)
- ✅ Развертывание на VDS сервере (Ubuntu 22.04)
- ✅ Авторизация и поднятие резюме
- ✅ Работа планировщика
- ✅ Автозапуск через systemd

### Известные ограничения
- API метод возвращает 405 (Method Not Allowed) — используется веб-автоматизация
- При частых попытках входа может появиться капча
- Резюме можно поднимать раз в 4 часа (бот настроен на 5 часов с запасом)
- На серверах с 512 МБ RAM Chromium может падать — рекомендуется 1 ГБ RAM или очистка зомби-процессов и swap
